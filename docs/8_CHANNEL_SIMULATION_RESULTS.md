# 8 通道同时录像模拟测试报告

日期：2026-10-30。软件：Camera Desk v1.1.1。

结论：1～8 路同时录像及录像中拍照的功能检查全部通过；8 路连续录像未中断。存在重复补帧，未达到本次“各路补帧不超过 5%”的实时性目标。

共验证 52 个视频、100 张照片，逐帧解码 59462 帧。视频尺寸、文件容器、帧数、录制时长及首／中／末的通道标识正确；照片尺寸、格式、数量及共同目录正确；没有保存弹窗、覆盖、意外停止或重启。

## 测试条件

- 本机 CPU：AMD Ryzen 9 9950X，16 核／32 逻辑处理器。Windows build 26100，Python 3.8.6，OpenCV 4.10.0。
- 运行 v1.1.1 正式界面和采集／编码代码，使用 1～8 个动态模拟源，Qt 离屏模式；不打开实体摄像头。应用的 10 个 Python 模块均与 v1.1.1 发行源码逐字节相同。
- 逐档测试采用 AVI。两项 8 路持续测试混合使用 AVI、MP4、MKV；720p 期间依次保存 PNG、JPEG、BMP、TIFF、WebP，1080p 期间保存 PNG、JPEG、BMP。
- 同一轮一次发出所有开始请求；各路只有一次开始和一次停止。各通道是独立文件，未提供硬件帧同步。

CPU 按 32 个逻辑处理器归一化，仅统计测试进程，不是整机总占用。心跳用于观察事件循环是否持续响应，不等同于鼠标操作的端到端延迟。

## 已确认的问题与适用范围

录像文件完整、时长正常，但部分新采样未进入文件，旧画面被重复写入以保持时长。该现象在低通道数也出现，不能据此认定为“达到 8 路上限”或 USB 带宽问题；本次未修改录制逻辑。

这些结果来自源码运行的正式流程及真实编码器；未对打包 EXE 进行 8 路测试。模拟场景较简单、采用离屏界面，本机 CPU 性能较高；不能推定其他电脑、复杂实拍画面、8 台实体 USB 摄像头或长时间连续运行会有相同性能。

本次仅新增可复现的测试脚本和测试记录，应用代码及既有 v1.1.1 发行压缩包保持原样。原始录像、照片及各轮 JSON 保存在 verification/8通道模拟测试 的正式测试子目录。
